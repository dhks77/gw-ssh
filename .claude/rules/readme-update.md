## README · CLAUDE.md 최신화

기능 변경 작업 후에는 해당 프로젝트의 `README.md` 와 `CLAUDE.md` 를 함께 확인하고 변경 내용을 반영한다.

- `README.md` — 사용자 관점 사용법/기능/설정
- `CLAUDE.md` — 개발자/에이전트 관점 내부 구조·제약·함정

### 적용 대상

- CLI 옵션/인자/서브커맨드 변경 또는 추가
- 새 기능/도구/엔드포인트 추가
- 기존 기능 제거 또는 정책 변경
- 설정 파일 필드 추가/제거
- 환경 변수, 빌드/실행 방법 변경
- 프로젝트 내부 구조(모듈 경계, 싱글톤/세션 수명, pipeline) 변경
- 리뷰어·기여자가 알아야 할 새로운 제약·함정·race 조건 발견

### 체크포인트

- [ ] `README.md` 사용법(Usage) 섹션에 신규/변경된 인자 반영
- [ ] `README.md` 기능 목록(Features) 에 추가/제거 반영
- [ ] `README.md` 설정 예시(config example) 에 새 필드 반영
- [ ] `README.md` 예제(Examples) 가 여전히 유효한지 재확인
- [ ] `README.md` 에서 제거된 기능 관련 문장/섹션 삭제
- [ ] `CLAUDE.md` 에 새 모듈/유틸/pipeline 추가 반영
- [ ] `CLAUDE.md` 의 "중요 제약과 함정" 섹션에 새 race/timing/경계 조건 반영
- [ ] `CLAUDE.md` 에서 제거된 구조/함수에 대한 서술 정리

### 작업 흐름

1. 기능 구현 완료
2. `README.md` 와 `CLAUDE.md` 현재 내용 읽기
3. 변경 diff 와 비교해 두 문서에서 수정이 필요한 부분 식별
4. 두 문서 갱신
5. PR 에 소스 변경 + 문서 변경을 함께 포함

### 이유

- 기능 구현 후 README 가 뒤처지면 사용자가 잘못된 사용법을 기반으로 시도 → 이슈 증가
- CLAUDE.md 가 실제 구조와 어긋나면 뒷사람(사람/에이전트) 이 옛 가정으로 수정 → 회귀 유발
- 코드 리뷰어가 문서로도 맥락을 파악 → 리뷰 품질 향상
- 코드/문서를 한 PR 에 묶어야 롤백 시 동기 이탈 방지
